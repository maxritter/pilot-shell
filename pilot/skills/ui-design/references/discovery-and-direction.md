# Discovery and Direction

Use this procedure for a new surface, a redesign, or any request whose visual direction is genuinely open.

## Read before asking

Inspect every supplied or discoverable source first:

- Existing components, tokens, themes, layout primitives, icons, fonts, and motion
- Adjacent screens and the same workflow at other states or breakpoints
- Brand guidance, screenshots, product copy, and user-supplied references
- The audience, primary job, and deployment context already stated in the request or repository

Summarize the visual vocabulary in working notes: palette and tone, typography, density, spacing scale, radii, shadows, component treatment, iconography, motion, and copy voice.

## Decide whether input is missing

Ask only when the answer materially changes what will be built. Typical blocking choices are:

- Primary audience or job when several incompatible flows are plausible
- Which brand or design system controls the work
- Target device or fidelity when it changes the implementation
- Whether requested alternatives should explore layout, interaction, visuals, or copy
- A product decision the repository cannot establish

Keep questions in one focused round. Do not ask for values already present in the code or assets, do not use a question quota, and do not pause for labels or other reversible details.

## Existing system

Preserve the current visual language. Lift exact tokens and component variants instead of recreating approximate values. Add a new token or variant only when the requested design needs a state the system does not represent.

An existing design system, established production UI, supplied reference, or explicit art direction owns the visual direction. Do not reopen visual direction with questions about vibe, palette, typography, or mood when those sources already answer it. Spend any necessary questions on audience, purpose, content, scope, structure, interactions, and copy tone instead.

If the current UI is inconsistent, report the inconsistency and select the most authoritative pattern: documented tokens and shared components first, repeated production usage second, isolated one-offs last.

## Greenfield direction

When no brand or system exists, define one coherent direction before high-fidelity work:

- Three adjectives tied to the audience and product purpose
- Specific, available type choices and a small type scale
- Palette roles, neutrals, semantic colors, and supported themes
- Density and spacing scale
- Radius, border, shadow, and component treatment
- Iconography, imagery, and motion behavior

If the user supplied no visual signal, ask one focused aesthetic-direction question rather than silently selecting the model's house style. If the user is unsure, propose two or three genuinely distinct directions. Specify the differentiating palette family, type treatment, density, layout character, and motion—not cosmetic variations of the same template. Recommend one and explain why it best serves the brief.

In an unattended run where no answer can arrive, derive from the audience, product purpose, existing materials, and brief, then state the assumed direction and why so the user can redirect it cheaply.

## Completion

Direction is settled when the existing system has been identified or a small greenfield system is documented, every material open decision is answered, and the first surface can be built without inventing further product scope.
