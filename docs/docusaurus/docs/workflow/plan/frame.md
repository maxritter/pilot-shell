The frame says what you want changed and how you will know it worked. The agent reads the relevant code first and asks only what it cannot find out itself.

![A frame: the problem, three numbered Done means, the questions decided with you, and the research questions](pathname:///img/diagrams/frame-light.svg)

## In the Cockpit

| Section | What it holds |
| --- | --- |
| Problem | What is wrong or missing today, in your words |
| Done means | The numbered, visible results you will accept the change by |
| Reference | A ticket or brief you gave, when there is one |
| Decided with you | The questions the agent asked, with your answers |
| Research questions | What the research must find out about the code |

`00-frame.md` is the version for you. `00-frame-details.md` keeps your request word for word and the starting points the agent found.

## When what to build is still open

If it is unclear who the feature is for or what the first version contains, the agent writes a fuller **product** frame, marked **Frame · product**. It adds the first release, what the user sees, how it reaches users, what is left out, and the sign that it worked. The design then only decides how to build it.

## You decide

Approve the frame, or comment and request changes. Done means is worth the most attention: every later check is measured against it.
